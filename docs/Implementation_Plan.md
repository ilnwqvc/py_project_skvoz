## Схема данных

raw:
JSON ответ API без изменений

normalized:
табличный слой после очистки и приведения типов
одна строка = одно наблюдение (час)

mart:
агрегированная витрина по дням
содержит KPI (средняя температура, осадки, ветер, дождливые часы)
используется для анализа и визуализации

## Почему слои разделены

Разделение нужно для:
- raw - хранит оригинальные данные (можно перепроверить)
- normalized - очищенные данные
- mart - быстрый анализ и KPI

Если делать всё в одном файле:
- сложно отлаживать
- нельзя переиспользовать данные
- выше риск ошибок

## Инкрементальность и идемпотентность

- Full режим используется для полной пересборки данных 
Данные извлекаются за весь период из конфигурации, слой normalized и mart пересоздаются полностью, а предыдущие результаты перезаписываются. 
- Incremental режим обрабатывает только новые данные, начиная с последнего сохранённого watermark, добавляет их в систему и исключает дублирование за счёт бизнес ключа

Состояние пайплайна хранится в файле data/state.json, где сохраняются last_watermark (последняя обработанная временная метка) и last_run (время последнего запуска) 
Business key для слоя normalized определяется как комбинация (city_id, ts), так как она однозначно определяяет каждую запись по городу и времени

Watermark обновляется только после успешного завершения всех этапов пайплайна, включая загрузку и формирование витрины, чтобы избежать потери данных при сбоях. Идемпотентность обеспечивается за счёт дедупликации по бизнес-ключу, пересоздания витрины в full режиме и корректной incremental логики без повторной обработки уже загруженных данных
