# Словарь данных для mart

Этот файл описывает витрину `mart` не как схему для разработчика, а как набор полей, с которыми будет работать человек в анализе.

Контекст витрины:
- 1 строка = 1 день по 1 городу
- текущий город в проекте: `JP_TYO` / Токио
- дата считается в локальной таймзоне `Asia/Tokyo`

| колонка | смысл | единица | пример / примечание |
|---------|-------|---------|--------------------|
| date | День, к которому относятся агрегированные погодные метрики | local date | Пример: `2026-02-25`. Это не timestamp, а именно календарная дата Токио |
| city_id | Код города, для которого рассчитаны метрики | identifier | Сейчас в данных только `JP_TYO` |
| T_mean | Средняя температура за день. Нужна, чтобы смотреть общую дневную динамику, а не отдельные часовые скачки | `°C` | Если в течение дня были значения 2, 4 и 6, то `T_mean` будет средним по всем часовым наблюдениям |
| P_sum | Сколько осадков выпало за весь день суммарно | `mm/day` | Если осадки шли в несколько часов, то значения складываются |
| wind_max | Самая высокая скорость ветра за день | `km/h` | Это не средняя скорость, а максимум среди всех часов суток |
| rainy_hours | Количество часов, когда осадки были больше нуля | `hours` | Если дождь был в 6 разных часах, то `rainy_hours = 6` |

## Как читать метрики правильно

- `T_mean` нельзя трактовать как температуру в конкретный час. Это усредненный показатель за день.
- `P_sum` зависит от зерна витрины. Здесь это сумма именно за день, а не за час.
- `wind_max` полезен для поиска экстремумов, но не показывает типичную скорость ветра в течение дня.
- `rainy_hours` показывает длительность дождя по часам, но не силу осадков. День с `rainy_hours = 2` может иметь больше осадков, чем день с `rainy_hours = 10`.

## Где эти поля создаются в коде

- `date` получается из `normalized.ts`
- `T_mean`, `P_sum`, `wind_max`, `rainy_hours` собираются в `build_mart()` в `src/transform.py`
